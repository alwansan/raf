T5 created a bounded CLR experiment rather than guessing Android game behavior:
- Exact source original `alwansan/raf@zip2` commit `15964ea8f246b6e076ce26b60931ee2e1a9a2385`; SHA-256 `0a6f0527856a9ce538d8d4217358b467c58fdcfad95e0ebebf9588c48f24f72e`, 3,211,776 bytes, independently checked before any method invocation.
- [Executable C# harness](../android-port/Experiments/T5/FileManagerRuntimeSandbox/Program.cs) resolves the **actual original compiled** direct method references with Mono.Cecil 0.11.5 and permits only a narrow validated call graph and absolute temporary synthetic file path before original managed invocation.
- [Thirteen explicit fail-closed report tests](../tests/test_t5_validate_filemanager_runtime.py) reject fake write/read success, omitted SHA/metadata, hidden failures, private method identifiers, Android/.rgd overclaims, symlinks and invalid JSON. The tool captures private CLR exceptions/output and publicizes only enumerated phase/count/error categories.
- [Isolated diagnostic workflow](../.github/workflows/raft-t5-filemanager-runtime-sandbox.yml) uses Ubuntu24.04/.NET9 and no Unity, game release, LFS, original save or proprietary artifact. It was changed to *manual workflow_dispatch only* once the same source-backed blocker was characterized, so later unrelated pushes do not burn runs or bury failures.
