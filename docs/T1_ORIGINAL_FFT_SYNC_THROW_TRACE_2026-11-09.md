## Proven gap and concrete fix

Previously the SHA-authentic Android-only wrapper staged `t1_original_fft_dispatch.before` and `t1_original_fft_dispatch.returned`, but if Unity `ComputeShader.Dispatch` synchronously threw an exception, only the Before remained. A missing After was ambiguous among synchronous throw, rotated/truncated log, logger I/O failure and abrupt process exit.

The source staging script now wraps *only on `UNITY_ANDROID && !UNITY_EDITOR`* both original direct Dispatch statements with `try { <UNCHANGED original Dispatch> ; AfterDispatch(sequence); } catch (System.Exception e) { DispatchThrew(sequence, e); throw; }`. Both non-Android and Unity Editor preprocessing paths retain the original Dispatch statements, not wrapping control flow. The `throw;` rethrows **the same original exception** with original stack; diagnostic helper catches its own logging exceptions. It never swallows or changes the real call, original kernel expression, groups, texture bindings, or metadata. No FindKernel invocation is added; compiled DXBC program slots are not interpreted as Unity runtime kernel IDs.

New `T1FftDirectDispatchTrace.DispatchThrew` emits `water/t1_original_fft_dispatch.threw`, bounded sequence, `managed_dispatch_threw=true`, a fixed safe `exception_kind` classification (`argument`, `invalid_operation`, `null_reference`, `other`) and explicit `original_runtime_mapping=unverified; gpu_result=unverified; water_rendering=unverified`. It **does not** log `exception.Message`, stack, private C# source, shader bytes or texture/pixel data. **It catches synchronous managed exceptions only**: warnings logged later by the Unity driver are still *not attributed* to the call.

The log parser `scripts/t1_fft_dispatch_pair_audit.py` and both native/legacy adversarial tests recognize `threw` as an exclusive terminal outcome. New `synchronous_thrown_sequences` and `unresolved_no_terminal_sequences` distinguish a known thrown call from one without any terminal. A `returned` and `threw` with the same sequence is contradictory: `conflicting_dispatch_terminal`, no positive pair. Cross-session/build provenance remains guarded. Every report retains `gpu_execution_proven=false` and `runtime_kernel_identity_proven=false`. Existing historical successful return-only cases remain parseable.
