## Authentic source defect

The real Android-only `android-port/Runtime/Platform/AndroidRuntimeLog.cs` used a process-wide static `readonly RepeatedDiagnosticMessages repeated`, but `Shutdown()` only sent pending `repeat_summary` groups and disposed the disk sink. The dedup table still retained every previously seen original exception stack even when a new `PersistentDiagnosticLog` session was created by a later `Initialize()` call in the **same managed process**. A repeated first error in a new session was suppressed by `UnityMessage` before `Write` and could never be found in that session's durable JSONL. This is a source-level fault; no owner device process restart or storage-failure incident is claimed.

The existing diagnostics .NET8 project compiles the **actual AndroidRuntimeLog production source** with `UNITY_ANDROID` and test-only `UnityEngineStubs.cs`. No implementation was copied. Existing fixture initializes a fake app sandbox, first encounters a path failure, restores storage, logs a synthetic full Unity exception, verifies durable JSONL `operation=Error` plus separate `repeat_summary`, and calls `Shutdown`. New fixture **reinitializes the real logger within that same process**, expects `UnityMessage(Error, identical stack)` to return `true` once in the new session and `false` for later exact duplicate; expects **two** distinct session primary JSONL files and exactly one original full Error in each across both sessions.
