## Scope and real evidence

The current native build pipeline stages W1 SHA-authenticated original graphics shader owners at `$RUNNER_TEMP/w1-original/Raft_Data` from pinned ZIP2. `scripts/hydrate_render_payloads.py` then checks remaining working graphics LFS pointers and fetches missing originals. B31 added a bounded SHA256/size-preserving cache reuse path plus a fail-closed linked-file check to this existing native-used script; **did not edit the shared native workflow or start a Unity build**.

The proposed savings hypothesis is **rejected for the current staging layout**: inspected the actual feature Git tree, all 14 independently pinned W1 shader-owner paths and the native workflow. Of the 14, **11 already contain full, ordinary Git blobs and exactly 3 are 134-byte LFS pointers** (`resources.assets`, `sharedassets0.assets`, `sharedassets36.assets`). Those three are **already materialized** by the preceding native ZIP2 staging step. Since hydration plans missing pointers only, **zero additional cache-reusable objects are demonstrated today**; do not claim any network, disk, build-time or completeness saving. The optional cache copy implementation remains useful only for future originally-pinned pointers present in the separately validated staging source. It validates exact feature LFS pointer identity, source SHA256/length, directory/file redirects and hardlinks, publishes each source atomically and falls back to unaltered Git LFS acquisition for absent objects. Missing/cache-invalid are distinct outcomes; an invalid present original aborts instead of silently trusting bytes.

A separate real bug in the production **texture coverage gate** is now guarded: earlier `scripts/audit_texture_stream_coverage.py` accepted an external `.resS` file through `Path.is_file()` even if the supposed original source was a symlink to another directory (or a hardlink to an external inode). This could produce `texture_covered` without establishing same-root provider provenance. The amended gate returns `unsafe_provider` for linked texture stream files, parent directories and linked/hardlinked serialized owner files, and counts it as a strict failure. The old valid covered/truncated, LFS-pointer and archive-prefix handling remain. Negative offset/size now fails before early inline handling. No game file bytes or texture pixels were changed.
