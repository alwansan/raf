# T4 LOCAL-005 — linear, fail-closed logger-session pairing in phone save/reopen evidence

**6 Nov 2026; owner T4**, session `20261106T1731Z-T4-chat-log-pair-linear-w6q2`, origin=chat. Production utility change [2e1417246a327e0a047d0817e328fd9d422b7c4c](https://github.com/alwansan/raf/commit/2e1417246a327e0a047d0817e328fd9d422b7c4c), with source-free red/green GitHub Actions.

## Concrete performance fault

In `scripts/t4_verify_device_world_save_log.py::summarize`, after validating up to `MAX_LINES=500000` JSONL lines, the source-free report used a comprehension over **every pair** of logger sessions and materialized `valid_pairs = [(i,j),...]`. The output, however, used only `bool(valid_pairs)` for both `save_nonzero_in_earlier_session` and `load_nonzero_in_later_session` hints. In a long app-log history with thousands of independent sessions, this makes the classifier quadratic in time and potentially in memory, even though no stronger game acceptance can be claimed from these hints.

The only allowed positive pair requires (a) no observed `logging/queue_overflow` in the entire report, (b) two **different** sessions whose individual sequences are complete and UTC is monotonic, (c) earlier session has a `save/Save.argumentFileSnapshot` classified `nonzero`, (d) later session has `save/Load.argumentFileSnapshot` classified `nonzero`, and (e) **strict** earlier last UTC < later first UTC. Neither pair nor duplicate/replay lines can establish an Android process restart, same world, serialized RGD integrity, or playability.

## Deterministic failure and actual optimized result

- Added a strict **synthetic-only** `tests/test_t4_verify_device_world_save_log.py` scenario with 200 distinct log sessions: first 100 save/nonzero then 100 load/nonzero, increasing UTC. A test-only wrapper around the real parser's `_parse_utc` counts timestamp comparisons, so the gate is **not dependent on CPU speed or an arbitrary timeout**. The existing verdict still must indicate both hints while keeping `process_restart_proven=false`, `cross_session_same_world_proven=false`, `real_rgd_durability_or_reopen_proven=false` and `local005_device_confirmed=false`.
- [**Red CI42262198164**](https://github.com/alwansan/raf/actions/runs/42262198164) on test-only [6f823443](https://github.com/alwansan/raf/commit/6f82344374bcbe91b6051a10f4a79f2c0262605b) **COMPLETED FAILURE**, `AssertionError: 20499 not less than 2000` comparisons. All other existing 27 parser controls passed; compilation and synthetic log analysis worked, and only the new bounded-comparison test failed.
- [**Fix 2e141724**](https://github.com/alwansan/raf/commit/2e1417246a327e0a047d0817e328fd9d422b7c4c) replaces pair-materialization with a linear pass over timestamp-sorted sessions. It tracks the **earliest finishing** eligible prior save and checks this end is **strictly before** a current valid load's first time. It updates eligible saved end **only after** checking that current session's load, so a save and load from the **same session** can never become a cross-session pair. If any source reported `queue_overflow`, the pair search still cannot set the positive hints. Existing sequence completeness and UTC monotonicity checks are unchanged.
- [**Green CI42262364475**](https://github.com/alwansan/raf/actions/runs/42262364475) **COMPLETED SUCCESS** on that exact code SHA: **28/28 synthetic parser checks plus 2/2 overflow-gate checks** (30 total). The many-session test satisfied <2,000 comparisons; positive hint semantics and false acceptance claims remained unchanged. Sorting individual session event rows and sessions by time remains, so no assertion of O(n) **total** parser runtime: the session-pair search is O(n), and sorting is O(n log n).
