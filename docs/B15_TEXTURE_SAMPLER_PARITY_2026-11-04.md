# B15 — Original Texture2D vs exported TextureImporter sampler fidelity (2026-11-04)

**Worker:** B15, session `20261104T215400Z-B15-7b2c`. **Issue:** RENDER-002 (P0). **Scope:** a read-only, authenticated tool, not an asset edit or white-material fix.

## Verified new engineering
- [Implementation](../scripts/b15_texture_sampler_parity.py) authenticates original Texture2D owners against three already-registered exact size/SHA256 pins (`resources.assets`, `sharedassets0.assets`, `sharedassets36.assets`) and ZIP2 commit `15964ea8f246b6e076ce26b60931ee2e1a9a2385`; prevents symlink/path-escape source/export files. This **does not** fetch or claim to validate the full 7.79GB source.
- A caller supplies a *same-export* explicit (source owner, pathID) -> (export asset, GUID) identity sidecar. The tool verifies typed original UnityPy `Texture2D` and the target `TextureImporter` YAML, rejecting duplicates, SHA/size/GUID drift, absent/ambiguous fields, invalid enums, nonfinite mip bias and file redirects. It never infers asset identities from names. `same_export_provenance_independently_verified=false` remains explicit because the caller's sidecar alone does not prove that both artifacts came from the same exporter invocation.
- Reads six original sampler fields: `m_FilterMode`, `m_Aniso`, `m_MipBias`, `m_WrapU/V/W`. Compares against corresponding exported importer settings with read-only aggregate mismatch/unknown counts; explicit `-1` importer override defaults are **UNKNOWN**, not falsely equal. Prints no object IDs, per-texture metadata or proprietary values; no file modifications.
- [Pinned upstream AssetRipperCLI `ImporterFactory.cs`](https://github.com/nowl-it/AssetRipperCLI/blob/036098ab525a3f9f693dc101edeb21faad4d32d8/Source/AssetRipper.Export.UnityProjects/Textures/ImporterFactory.cs) contains `instance.TextureSettings.CopyValues(data.TextureSettings)`. Therefore upstream intent is to **preserve** sampler settings. This is an import-parity guard for possible downstream drift, **not evidence that the exporter is known to drop sampler settings** or that sampler settings cause the owner's white-material symptoms.

## Follow-up: original/export identity trace bridge — tested 16/16

B15 subsequently added `sidecar_from_export_trace(project, trace)` and an opt-in `--trace` CLI input. It consumes the **same-instance exporter object trace schema** already used by B05 (typed classID 28, source owner/pathID, exported PPtr fileID/GUID/type). For the **three trusted pinned owners only**, it discovers exported texture files by an exact, unique Unity TextureImporter `.meta` GUID match, never filenames or colors. It fails on missing/ambiguous GUID targets, invalid target types, source paths with traversal, duplicate rows and non-TextureImporter targets. Derived sidecars stay **in memory**: raw trace, proprietary names, GUID mappings and source contents are never emitted in public outputs. All source bytes remain read-only.

Corrected a specific **false-positive class**: Unity's [TextureImporter.mipMapBias documentation](https://docs.unity.cn/Documentation/ScriptReference/TextureImporter-mipMapBias.html), also documented in [2019.4](https://docs.unity.cn/2019.4/Documentation/ScriptReference/TextureImporter-mipMapBias.html), states the importer's default `-100` means the property is **invalid/unset**. The B15 tool formerly classified this as a hard `m_MipBias` mismatch against the original `Texture2D`. It now counts exact `-100` in `unresolved_importer_defaults`, leaving `metadata_fields_faithful=false`; real `-0.5` drift is still detected. Existing `-1` import enum defaults remain unknown rather than falsely equal.

Added optional `--companion-trace <private-W1-Material-Shader-trace.json>` when using `--trace`. The tool checks that both the B02 `Texture2D` (classID28) and pinned W1 `Material/Shader` (classes21/48) traces have matching 32-hex `export_instance` values, schema version1 and typed W1 source identities; refuses mixed export sessions, invalid object classes, missing rows, malformed source fields and linked/oversized private trace files. Output exposes only an aggregate boolean `companion_export_instance_matched` plus `paired_trace_provenance_independently_verified=false`. This aligns with [B02's compiled optional class28 exporter hook CI41927712988](https://github.com/alwansan/raf/actions/runs/41927712988), which can emit both traces with the same instance ID during one private export. A matching self-reported ID is **necessary but not independent provenance proof**.
