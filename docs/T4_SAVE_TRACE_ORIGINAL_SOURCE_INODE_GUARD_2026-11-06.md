# T4 LOCAL-005 — protect original SaveAndLoad tracing from upstream hardlink aliases

**6 Nov 2026.** T4 chat `20261106T1810Z-T4-chat-save-trace-hardlink-s9m4`, origin=chat. This source integrity fix is part of **preserving authentic original Raft C# and GUID sidecars**, not a rewrite of SaveGame/.rgd or proof of native gameplay.

## Real original operation-tracing surface

The SHA-authenticated original-source tracer `scripts/instrument_android_runtime_operations.py::apply` stages original `Assembly-CSharp` files including SaveAndLoad/Raft_Network and optional `.cs.meta` before adding Android-only diagnostics for original world, SaveGame, SaveWorld, SaveUser and Load<T> boundaries. It checks symlinked project, source and backup ancestors, manifest revision SHA, unique file paths, and original backup separation. However, a **hardlinked** source or `.meta` is a regular file and passes these checks. With a hardlinked source, `path.write_bytes(instrumented_source)` writes into the same inode as a source outside the project, potentially destroying the independent original on a retry; previous T4 guard [e88c54fa](https://github.com/alwansan/raf/commit/e88c54fa3f2add8cb05397a1cd8f90ab53fec2a7) only protected the *separate* offline source adapter, and the original Save path converter protected its own stage. An independently invokable operation-tracer must also reject such inputs.

This is a proven **possible** unsafe staging path on disposable synthetic files, **not** evidence that current ZIP2, original Raft, or user RGD has been damaged.
