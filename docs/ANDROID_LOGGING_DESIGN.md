# LogRaft engineering decisions\n\nSee [README](../README.md). The source branch `feature/android-native-port` is read-only for this logger project; `lograf` is writable. Game package `com.alwansan.raft.androidtest`; Unity's own diagnostic JSONL logs are stored under the game sandbox.\n\n## Why Shizuku remote service?\nAndroid 13+ limits background capture via ordinary application READ_LOGS even if granted. Shizuku UserService runs shell/root, starts two streams, forwards only Raft UID records and Raft-related system context into SAF. This is bounded in memory, not on disk; files rotate without deletion. The foreground notification communicates active user-requested recording.\n\n## Risks\nNo complete capture guarantee across process death, OS policy or full storage. Backpressure through Binder can cause Android's own Logcat ring to overwrite earlier events. Consider additional on-device Unity first-failure diagnostics and session-level coverage counters after physical testing. Hardware validation is mandatory.\n
