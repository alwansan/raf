## Why this approach, not only OpName

Prior actual SHA-authenticated original [42274933802](https://github.com/alwansan/raf/actions/runs/42274933802) confirmed aggregate 44 original DXBC DCL CB/SRV/Sampler resource declarations versus corresponding translated SPIR-V family totals over 8 original Shader48 stages, but stage-to-stage counts and source register → Vulkan target descriptors remained unproven. Shader48 is still `DummyShaderTextExporter`; real owner phone colors/white raft/hand, square smoke, candle/fire FX remain OPEN.

Our previous `OpName` heuristic is weak: optional debug names may be absent or misleading. **B18** already proved that VKD3D's public `vkd3d_shader_interface_info` C ABI can compile authenticated original FFT DXBC with two *explicit*, chosen source register → Vulkan binding profiles (CI41930824777), and two such SPIR-V programs can be byte-identical after masking only descriptor literals (CI41931883517). This is an evidence-backed approach to transfer to Shader48 graphics VS/FS, but those FFT successes **are NOT shader48 results**.
