## Engineering hypothesis and confirmed incompatibility

Actual `android-port/Runtime/Platform/PersistentDiagnosticLog.cs` emits newline-delimited JSON rows with `area`, `operation`, `detail`, top-level `session` and a **global logger** `sequence`. `T1FftDirectDispatchTrace.cs` supplies the FFT callback `operation=t1_original_fft_dispatch.before/returned` and a **separate bounded dispatch** `sequence=1..16` inside `detail`. The previous `scripts/t1_fft_dispatch_pair_audit.py` only read `event` and `message` and thus silently ignored real native records. Its prior identity keys also omit the original hook's `numeric_kernel_argument` and `shader_instance_session_local`, so they cannot prove runtime shader/kernel identity.
