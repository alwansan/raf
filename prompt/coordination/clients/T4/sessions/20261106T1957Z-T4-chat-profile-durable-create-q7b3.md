- **Actual source defect:** `LocalProfileStore.GetOrCreateProfileId()` creates a unique 32-hex offline identity in `profile.id`, mapping via `LocalPlayerIdentity.FromProfile` to the stable original offline save/player key. The prior `StreamWriter.WriteLine`+Dispose did not explicitly request OS flush-to-disk before returning that identity. More importantly, an `IOException` thrown *after* a successful `FileMode.CreateNew` (during WriteLine, StreamWriter.Dispose, or disk sync) entered a broadly scoped catch `when (File.Exists(path))`, suppressing the write failure merely because the newly-created file existed. This could report a valid first identity without a successful explicit flush; it was not observed on owner phone and is not a proven cause of past user save problems.
- **Compiler-IL-level RED negative control:** [test-only 31a7cd97](https://github.com/alwansan/raf/commit/31a7cd97c4ad9cd101a532895334d11bb0f778ee) adds an actual .NET8 CLR IL decoder for `LocalProfileStore.GetOrCreateProfileId()`. It locates a call to `FileStream.Flush(bool)`, and checks that the flush instruction offset is **not inside any filtered CreateNew collision catch's protected try range**. Also retains all existing valid identity, isolated worlds, and no-cloud host tests. - **Minimal actual Android platform source fix:** [e9e6c0c7](https://github.com/alwansan/raf/commit/e9e6c0c7c6f4d9cc9fe304e69394a45be48b5e12) changes only initial `profile.id` creation.
