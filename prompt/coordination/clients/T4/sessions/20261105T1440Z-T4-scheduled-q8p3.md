## Observation
Source-free JSONL verifier currently checks per-session sequence continuity and global first/last UTC boundaries but does not check whether increasing sequence values have nondecreasing UTC values. A clock rollback, corrupted UTC row, or reordered event can therefore yield a misleading cross-session save/load *hint*. This is not game acceptance: existing verifier always reports device_confirmed=false.

## Planned isolated fix
Store each validated row UTC by sequence, flag utc_reverses_sequence on any later sequence with earlier UTC, and exclude sessions with this anomaly from cross-session hint pairing. Add negative control with inverted sequence UTC, and one ordinary monotonic control. Also require sequence_complete for both paired sessions. Never publish raw logs, paths or IDs.
