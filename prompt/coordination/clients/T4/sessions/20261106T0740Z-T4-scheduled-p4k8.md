## New bounded source fix
RequestCapture previously retained captureViewIdentity from the previous epoch until UI thread accepted a new focused View. If no focus was available, a queued ProbeCapturedPointer could see identity zero and accept an unrelated View's hasPointerCapture because mismatch was tested only for nonzero requested identity. Now each RequestCapture epoch resets captureViewIdentity to zero and ProbeCapturedPointer rejects identity zero OR mismatch, calling ObserveNativeCapture(token,false) before reading the other View's capture. Existing original Unity axis fallback remains. This is a fail-closed safety correction, not a claim that the scenario occurred on phone. Added source regression in tests/test_t4_pointer_view_identity_contract.py.
