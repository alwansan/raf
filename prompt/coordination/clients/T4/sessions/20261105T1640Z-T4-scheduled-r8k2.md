## Checked live evidence

The current source-free Android JSONL analyzer `scripts/t4_verify_device_world_save_log.py` (blob SHA 98cb952f0abb475d8fe41698eb3156c79d97ebf6) sets `invalid_truncation=True` on `logging.queue_overflow` and continues without attributing the overflow to a session. Its `valid_pairs` predicate checks session completeness, UTC monotonicity, and earlier nonzero Save/later nonzero Load; it **does not inspect invalid_truncation**. Therefore a constructed input consisting of one overflow record, a complete earlier Save snapshot session, and a complete later Load snapshot session can yield `save_nonzero_in_earlier_session=true` and `load_nonzero_in_later_session=true` while `logging_queue_overflow_observed=true`. This is a static source-derived counterexample, **not a run of the proposed fixture**.

This is not a game-world defect or proof of lost saves. It is a possible misleading positive evidence hint under known dropped log events. Because the overflow marker is not attributed to a session in the current implementation, the conservative fix is to suppress both positive cross-session hints whenever global overflow is present, while preserving raw marker counts and reporting the overflow. Add a synthetic negative test and positive no-overflow control. Do not interpret absence of marker as proof of no overflow.
