## Concrete code-path audit

Read android-port/Runtime/Platform/AndroidTouchPointer.cs on baseline. It adds a **synthetic** InputSystem Mouse named RaftAndroidTouchLeft, consumes Touchscreen StateEvent, and injects only MouseButton.Left; physical Mouse is explicitly not intercepted. It uses legacy Input.GetKey for keyboard/real Mouse0 and ORs synthetic left mouse for gameplay. Thus changing this adapter to swallow all mouse events would break physical mouse and keyboard semantics. It does not request Android View pointer capture, does not consume native relative AXIS_RELATIVE_X/Y, and cannot on its own prevent Android system edge gestures. This is a missing integration boundary, not proof of Unity camera input bug.
