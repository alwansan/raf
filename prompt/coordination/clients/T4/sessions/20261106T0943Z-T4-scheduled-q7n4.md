## New source audit: release target mismatch
Read current android-port/Runtime/Platform/AndroidPhysicalMouseCapture.cs at baseline. Checked method-local presence of getCurrentFocus and captureViewIdentity for RequestCapture, ProbeCapturedPointer and ReleaseCapture. All three query focus independently. RequestCapture stores the requested View's System.identityHashCode; ProbeCapturedPointer compares it and fails closed. **ReleaseCapture clears captureViewIdentity before queuing its Android UI-thread closure and then calls releasePointerCapture only on a fresh getCurrentFocus View, without checking whether that View is the original capture target.** If focus changes between request and release, this code may not explicitly release capture on the old View. This is a source-level gap, NOT proof of a leaked capture on Android: the OS may release capture automatically on focus loss.
