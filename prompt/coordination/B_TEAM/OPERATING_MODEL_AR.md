# الأولويات والتعاون — فريق B
## توزيع ذاتي مرن
الهدف لكل عامل تنفيذ هندسي ودمج نتائجه. ليست هناك وظيفة أبدية بحسب الرقم. ابدأ من المشكلات المفتوحة ذات الأثر الأعلى، ثم dependency التي تعطل غيرها. سجّل track وapproach والملفات والتجارب قبل العمل. اختر أقل نهج مفيد تغطية داخل الأولوية الأعلى، ولا تنضم إلى تجربة مماثلة لمجرد أن هدفها مهم.
توزيع افتتاحي إرشادي عند نشاط50عاملاً:18للماء/FFT والشيدرات،10للألوان والخامات والمؤثرات،12للعالم/الحفظ المحلي،6للموارد/meshes والربط،4للدمج والمقارنات والتحقق. ليس تعييناً ثابتاً ولا ادعاء بوجود50عاملاً نشطاً. إذا كان العدد5مثلاً فليغطوا النهج الأساسية P0 أولاً. ينتقل العامل بعد إنجاز نطاقه أو ثبوت انسداد نهجه إلى فجوة أخرى قابلة للعمل.
داخل هدف واحد يمكن5–10أو أكثر أن يعملوا بالتوازي على أصل البيانات، disassembly/translation، resource binding، CPU/GPU numeric/pixels، material integration، regression review. لا يوجد رئيس إلزامي ينتظر الجميع موافقته. اجعل نقطة دمج الملفات المشتركة واضحة في نقاش مستقل.

## حالات الأدلة
- OPEN: عائق أو مجهول مؤثر.
- IN_PROGRESS: عمل جارٍ مع work/session/run محدد؛ غياب heartbeat ليس برهان توقف.
- SOURCE_FIXED: تغيير فعلي وcommit واختبارات، ولم يثبت runtime بعد.
- INTEGRATED: مستخدم في المسار الفعلي مع integration evidence؛ ليس قبول هاتف.
- DEVICE_CONFIRMED: نتيجة هاتف مربوطة بـAPK/version/source وملاحظات المالك.
- OWNER_CONFIRMED: ملاحظة المالك محددة النطاق، لا تعممها على كل المحتوى/الأجهزة.
- DEFERRED: مؤجل بقرار المالك، وليس مكتملًا.
- BLOCKED: سبب ودليل وخطوة بديلة. لا تنتظر إن كان مسار آخر مفيد متاحاً.

انتهاء work لا يغلق issue تلقائياً. لا تغلق WATER بسبب validator أو kernel عددي واحد، ولا العالم بسبب عبارة World has been loaded. لا تثبت خسارة meshes من اللون الأبيض؛ افصل mesh geometry/stream bounds عن shader/material/textures وlighting/sRGB.
الموارد لها evidence لكل مرحلة: acquisition، extraction، reconstruction، binding، integration، runtime/device. أرقام الملفات/البايتات تعني تغطية الجرد فقط. لا نسبة اكتمال كلية دون denominator وقائمة قبول ثابتة ونطاق؛ unknown=null وليس0أو100.

## البناء والأدوات
توجيه المالك الحالي يتيح لفريق B التجارب اللازمة بما فيها Unity وتجارب رسومية/بناء تشخيصي؛ لا تفرض عليهم حدود CPU-only الخاصة بدور تاريخي. لا يبدأ إعداد الفريق أي build. استخدم تجربة صغيرة تحسم السؤال أولاً عندما تكون أنسب، ولا تكرر full export إذا يمكن إعادة استعمال artifacts/binaries الموثقة.
التجارب الخاصة قد تضاف على raf-archive في فرع تجارب باسم Bxx/experiment وتقرير آمن في raf؛ لا تحذف أو تستبدل Release الأصلي أو أصوله أو main. إذن مستودع الاختبار الخاص لا يعطي صلاحية لتعديل main/zip/zip2/Unity-Editor في raf.
احترم الصلاحيات الفعلية للأداة والـtoken وحصة Actions. لا ترفع الميزانية أو تغيّر الحساب/الفوترة/الخصوصية لتجاوز حد. إذا توقف private compute استخدم بيئة محلية مصرحاً بها، أو CI العام القياسي للكود الآمن فقط مع مصدر خاص في temporary وعدم نشره. لا تعالج نفاد الحصة بحلقة retry.
حرية البحث لا تبرر تغيير الأصل إلى placeholder أو تعطيل الماء أو إزالة المحتوى/الجودة لإظهار النجاح. بديل shader يجب إثبات تطابقه، لا تكتفِ بعدد passes. نظام local offline بديل مطلوب للـSteam/Party حيث يلزم فعلاً، وليس خادمًا وهميًا أو نجاحًا مصطنعًا؛ حافظ على gameplay/save semantics ورسائل الأخطاء الحقيقية.

## الحفظ والتزامن
اكتب حدثاً مستقلاً عند discovery/start/result/integration/closure/failure. في كل checkpoint جدّد state/MEMORY/work، وأضف ما ثبت لملف issue أوresource ببصمة المصدر والأدلة والحدود، ثم شغّل المولد. الملف المولّد لا يفرض تحديثاً إذا لم تتغير المدخلات.
لا حجوزات للعملاء القدامى بعد تقاعدهم بتوجيه المالك؛ لا تغيّر سجلاتهم لتبدو من صنع B. أي تحسن سابق يُنسب لدليله ويُستخدم بدلاً من إعادته. أعمال B الحالية تنسق عبر plan وdiscussion، وليس ملكية حصرية لمشكلة كاملة.
أبقِ جلسات متعددة لنفس الاسم منفصلة عند الشك. session_id فريد ضروري للأسماء/التجارب/artifacts. Git lease يحمي رأس الفرع فقط، وليس صحة دمج منطقي؛ اقرأ الملفات عند تغير الرأس.
لا يصنع هذا النظام جدولاً أو جلسة مستمرة. لا تنشئ خمسين cron أوتوماتيكياً، ولا تُعد تفعيل المهمات القديمة؛ المالك يشغّل العملاء المسماة.
