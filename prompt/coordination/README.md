# تنسيق عملاء Raft

ابدأ من [البرومبت الموحد](UNIFIED_PROMPT_AR.md)، أو [استعادة عميل](RESTORE_CLIENT_AR.md). هذا سجل تعاون عبر Git، وليس اتصالاً فورياً أو مشغلاً للجلسات.

## البنية

- clients/<username>/state.json: الهوية والحالة والعمل الحالي وآخر heartbeat وSHA.
- clients/<username>/MEMORY.md: الأدلة والقرارات وآخر نقطة والخطوة التالية.
- work/<issue-id>/<username>-<work-id>.json: خطة العمل والملفات المقصودة وحالة الإنجاز.
- discussions/<issue-id>/<UTC>-<username>-<id>.md: رسالة مستقلة؛ الرد في ملف جديد مع رابط الرسالة الأصلية.
- experiments/<username>/<experiment-id>.json: فرضية ومدخلات وبصمات وأوامر ومسار workflow وروابط ونتيجة وحدود.
- incidents/<username>/<incident-id>.md: العطل ودليله وأثره وخطوات الاستعادة والحالة.

أنشئ المجلدات والملفات عند الحاجة. لا تستخدم ملف سجل مشتركاً يكتب الجميع فوقه. اسم المستخدم هو اسم مستعار داخل المشروع وليس حساب GitHub أو إثبات هوية.

## قواعد التزامن

1. اختر raft-<UTC compact>-<random8> وتحقق أن clients/<username> غير موجود. سجل session_id عشوائياً جديداً لكل جلسة.
2. يمكن لعدة عملاء العمل على المشكلة نفسها؛ سجل المشكلة والنهج والملفات قبل التنفيذ. لا توجد ملكية حصرية للمشكلة.
3. state: active / paused / blocked / completed. حدث heartbeat عند كل checkpoint وقبل/بعد تجربة طويلة. بعد60 دقيقة دون تحديث تعتبر الحالة possibly_stale للمراجعة فقط؛ لا تلغِ jobs ولا تستولِ على جلسة بسبب الوقت.
4. قبل تعديل ملف يغيره آخر، اقرأ خطته وأحدث المصدر ونسّق برسالة. طوّر تجربة مستقلة أو جهّز patch ثم ادمج من أحدث HEAD؛ لا تحجز المشروع كله.
5. كل commit يبنى على HEAD حي وبملفات محددة وexpected SHA دون force. عند رفض lease أعد القراءة والدمج؛ لا تعاود الكتابة بنفس المحتوى القديم. لا reset/clean لعمل الغير.
6. اقرأ plans وexperiments وActions قبل إطلاق أي تجربة. التكرار مسموح إن كان تحققاً مستقلاً مقصوداً وله سبب مسجل. الملف المنفصل لا يبرر إعادة تنزيل LFS أو استهلاك الموارد بلا حاجة.
7. للتجارب CPU-only المتزامنة استخدم workflow ومسارات تقارير وartifacts وconcurrency group فريدة باسم العميل/التجربة، cancel-in-progress:false، timeout وميزانية معلنين. لا تعدل workflow جارياً أو native request أو تبدأ Unity لتفادي ازدحام مسار آخر. مسار البناء الكامل يبقى تحت شروط الجاهزية الحالية.
8. لا تنقل مصادر خاصة أو شيدرات خام أو أصول أو مفاتيح إلى السجل. سجل size/SHA والنتائج المجمعة وروابط الأدلة. unknown ليس success وCI ليس اختبار هاتف.
9. عند النهاية حدث state والعمل إلى completed أو paused/blocked بدقة، مع آخر commit والاختبارات والمتبقي. completed يعني انتهاء العمل المحدد لا اكتمال اللعبة. لا تحذف التاريخ؛ التصحيح برسالة تربط السابق.
10. قبل كل دورة اقرأ الحالة الحية، لا تفترض أن العملاء يقرؤون فوراً. سجل الرسائل المقروءة في MEMORY. التعارض غير المحسوم يبقى incident؛ لا تفرض قراراً على عمل الغير.

## الاستعادة

الاسم وحده يكفي لتحديد المسار عند إرسال برومبت الاستعادة. لا تستأنف هوية نشطة تلقائياً: راجع heartbeat وsession_id وActions. إن كانت الجلسة الأصلية ربما نشطة، أنشئ هوية جديدة مرتبطة بـ resumed_from بدلاً من الكتابة على ذاكرتها. لا يمكن إثبات توقف جلسة من غياب heartbeat وحده.
