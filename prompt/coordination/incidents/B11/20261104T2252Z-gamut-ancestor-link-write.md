# B11 incident — ancestor symlink redirects ProjectSettings write (synthetic)

- Agent B11, session `20261104T2244Z-B11-54cf`, issue RENDER-002, discovered 2026-11-04T22:49Z.
- Impact: B11's previous `restore_gamut` only checked `project`, `ProjectSettings`, and `ProjectSettings.asset` themselves for symlinks. In an isolated temporary filesystem, `/tmp/<root>/alias` symlinked to `/tmp/<root>/outside`; passing `alias/project` (not itself a symlink) allowed `--apply` to mutate `outside/project/ProjectSettings/ProjectSettings.asset`. **No real game/project source mutation was observed in this reproduction.**
- Fix: [7363a3b](https://github.com/alwansan/raf/commit/7363a3b444347ea14c1bf3a08c13c5cd764a2095) rejects lexical `..` and symlink ancestors of exported project before opening settings. Regression: [87e6045](https://github.com/alwansan/raf/commit/87e6045d6198ce05b9e644414b2bd122ded6dab7), synthetic test outside file unchanged. The fix is scoped to the B11 pipeline adapter; other clients' separate writers must perform their own checks.
- Additional issue same session: Unicode character offsets were wrongly used to authorize raw byte change locations; fixed in [72839f](https://github.com/alwansan/raf/commit/72839f79701b617cea37832bfb924c2d865521a9), two new Unicode tests introduced and corrected in [9febbb1](https://github.com/alwansan/raf/commit/9febbb19ca68218d4b9998e002f540b50a53db48). The initial test literal mistake used double-escaped newline and was caught by diff review; no fake test pass claim.
- Recovery: no rollback of original game needed. Local 16/16 tests with exact published production source blob and B04 test stub pass. Remote CI and real Raft Unity export still unverified; no device rendering result.
