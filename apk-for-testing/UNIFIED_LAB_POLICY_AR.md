# قرار المالك — 8 نوفمبر 2026: APK واحد وTestpack واحد لجميع T1–T5

**هذا البروتوكول يحل محل تعليمات إنتاج تطبيقات T1–T5 المنفصلة في LAB_PROTOCOL_AR.md، ولا يمحو تاريخ تلك الإصدارات أو تجاربها.** لا يتغير تصويت `prompt/coordination/T_TEAM/TRIAL_BUILD_READINESS.md` على بناء **لعبة Raft الكاملة XAPK**، ولا جاهزية اللعبة 3/3.

## المنتج الواحد
- المصدر المعتمد الجديد: `apk-for-testing/unified/`، التطبيق **com.alwansan.raft.lab.shared**. صفحة المالك الوحيدة: `apk-for-testing/TEST_CENTER.md`، ورابط APK **حقيقي مباشر** بعد تحقق T5 من أصوله وإتاحته، ورابط **ملف testpack واحد** (أو ZIP بيانات واحد) فقط. لا تطلب تثبيت خمسة تطبيقات مستقلة. لا تحذف builds T1..T5 القديمة؛ تصبح مراجع تاريخية، وليست خيارات التنزيل الأساسية.
- وحدة واحدة للأعمال الخمسة (GPU T1، ماء T2، رسوم T3، ماوس T4، قياس/حزم T5). كل عامل يصمم حالات عمله من المصدر الأصلي الموثق، ويسلم case IDs/driver/parameters/evidence إلى مجلد خاص به؛ الدمج المركزي عند T5. لا يغيّر عامل مصدر نشاط زميله دون تنسيق؛ مراجعة diffs/HEAD/CI وleases ضرورية.
- الحزمة الموحدة: `apk-for-testing/unified/pack/team-testpack.json`، JSON **بيانات فقط**، مضمّنة افتراضياً داخل APK ومحملة آلياً عند فتحه. تستطيع اختيار نسخة أحدث عبر SAF إن كانت متوافقة مع drivers المثبتة. لا تنزيل كود Java/DEX/SO/GLSL قابل للتنفيذ من pack مجهول. **الحزمة لا تستطيع إضافة driver جديد غير موجود في APK**؛ عند تغيير المحرك/renderer أو GPU shader المدمج يلزم APK جديد. SHA256 للحزمة ونسخة driver وcase revision لتحديد حداثة النتائج.
- اضبط كل case `worker,id,driver,revision,automation,screenshot,title,instructions,expected`. مالك case وحده يغير حالته/تعريفه، بمعرّف ثابت؛ T5 يراجع التجميع. حماية اختبار JSON وفق schema، حد الحجم والـSHA، لا مسارات absolute أو path traversal أو مصادر خاصة.

## واجهة واحدة واستراتيجية التشغيل
- شاشة افتتاحية بها T1,T2,T3,T4,T5، تقدم كل عميل، **Auto Test All** و**Auto Test Tn**، وقائمة **طلبات داخل التطبيق** واضحة، و**Next/Finish**.
- الضغط مرة واحدة يشغل **كل الحالات القابلة للأتمتة فعلاً** بالتتابع وبمهلة timeout، ويسجل PASS فقط من assertion حقيقي. عند تعذر GPU/context/ملف/تصريح أو الحاجة إلى حركة ماوس مادية: اكتب `BLOCKED/NEEDS_INPUT/PENDING_VISUAL`، لا تزوّر النجاح أو تتجاهل الاختبار، وأنشئ طلباً واضحاً للمستخدم داخل التطبيق. أي اختبار يحتاج المستخدم يظل في قائمة المهام حتى تكتمل أدلته؛ زر **Next** ينقله إلى التالي و**Finish** يعيد للقائمة.
- السكرين شوت **عند الحاجة فقط**: اختبارات graphics تلتقط صورة من **نافذة تطبيق المختبر نفسه** عبر PixelCopy عند نجاح الوصول للصورة، وتحفظها مع case ID/لقطة SHA/URI/وقت. إذا فشل الالتقاط تصبح `PENDING_SCREENSHOT`، وتُعرض في قائمة داخلية؛ يسمح `Attach Screenshot` باختيار صورة موجودة عبر SAF، أو يفتح الاختبار للمستخدم لالتقاط صورة ثم إرفاقها. **لا يستطيع التطبيق تصوير Raft أو تطبيقاً آخر صامتاً**. لا تفترض وجود لقطة إذا نقر المستخدم على Next فقط.
- **عدم إعادة الاختبار** يعتمد على case revision + driver version + APK build identity + pack/inputs digest + الجهاز/الإعدادات ذات الصلة؛ وللصور، يجب التحقق أن ملف صورة الـMediaStore ما زال موجوداً ويمكن قراءته. إذا غيّر العامل case/revision أو الصورة مفقودة، تعاد تلك الحالة وحدها. النتائج الفاشلة لا تخفى أو تتحول PASS، ويمكن استعمال Force Rerun للبحث.
- كل جلسة تنتج `events.jsonl`، و`summary.json`، وملفات صور فعلية عند وجودها في `/storage/emulated/0/Download/Games/cl/test/<shared-session>/` عبر MediaStore/SAF Android15، مع private checkpoint قبل التصدير. عند فشل التصدير تعرض error ويمكن استعمال Save As؛ لا تطلب تخزين كامل/روت. LogRaft اختياري للمشاكل الخارجية وليس شرطاً أو مزود صلاحيات.

## جاهزية بناء Mini APK مشتركة (مختلفة عن تصويت XAPK الكامل)
- كل عامل T1–T5 يحدّث **صفه وحده** في `apk-for-testing/SHARED_BUILD_READINESS.md` بعد دمج **تغيير جوهري** أو testpack موحد يحتاج التحقق على الهاتف: **NEED_BUILD** أو **NO_BUILD** أو **WAITING_MERGE** مع السبب، SHA/CI، والحالات التي يريد اختبارها. لا يصوّت أحد نيابة عن الآخر.
- **إذا صوت الخمسة NEED_BUILD** فهذا إجماع واضح. **لكن لا ننتظر الخمسة**: يحق لـT5 إنشاء بناء Mini واحد عندما يطلب **عامل واحد على الأقل NEED_BUILD** مع تغيير فعلي ومتكامل بالـAPK يستدعي إعادة بناء؛ بعد فحص CI/HEAD وrunning jobs وتوقيع الحزمة والاختبار والمخاطر. لا تجبروا الباقين على NEED_BUILD. لا بناء لملفات JSON أو وصف تعليمات فقط إن كانت النسخة القديمة تستطيع استيرادها: صدّر **pack واحداً جديداً** فحسب.
- تجنب build مكرر بنفس driver+source fingerprint، ولا تبدّل build request موجوداً أو تلغِ Action. تفصيل آلية طلب المصغر في BUILD_REQUEST_AR.md؛ T5 وحده صاحب طلب **المختبر الموحد**. توقيع وpackage ثابتان لحفظ نتائج وصور التطبيق عبر التحديثات. لا تغيّر عشوائياً debug keystore، وقارن signer certificate؛ إن كان التوقيع الحالي مؤقتاً لا تعد المستخدم بترقية بلا uninstall.
- رابط **Direct Download** في المركز لا يُكتب قبل أن تتحقق صلاحية URL فعلي خاص بالأصل APK/pack. صفحة artifact ZIP ليست direct APK؛ إن كانت GitHub Actions ZIP فقط، اذكر ذلك بوضوح وقدّم رابط صفحة Artifact كخيار بديل دون الادعاء بأنه تنزيل APK مباشر. النشر العام لملفات proprietary ممنوع؛ لا تُضمّن خامات/ملفات Raft المحمية في إصدار عام.
- كل عامل يواصل عمله ويستطيع مساعدة عامل آخر عند انتهاء نطاقه وانتظار نتيجة الهاتف، لكن لا يوقف العمل الطبيعي أثناء build.
- لا تعدّل `main`/`zip`/`zip2`/`Unity-Editor` ولا `CL`. فرع الكتابة الوحيد `feature/android-native-port`. احفظ state/MEMORY/session مستقل origin chat/scheduled وحدث الأدلة والتقدم.
