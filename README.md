# RAFT: مختبر أندرويد منفصل

هذا الفرع مستقل بمحتواه: لا ينسخ CP، ولا يحمل كود اللعبة أو أصولها، ولا يبني XAPK. دفع تغييرات لهذا الفرع فقط يشغّل فحصاً على Android API 35 في GitHub Actions. النتيجة لا تغلق أي بوابة RAFT ولا تعوّض تجربة الهاتف.

- يختبر كل Runner معماريته وصورة Android المطابقة وتسريع KVM؛ لا يعتبر محاكاة x86 دليلاً على ARM64. إذا تعذّر محاكي ARM64 أو KVM يظهر الفشل مستقلاً ولا يتحول إلى نجاح x86.
- يبني APK اصطناعياً جديداً، يثبت التطبيق ويشغله، ويصوّر شيدر OpenGL ES بسيطاً ثم ينقر بـ adb ويتحقق من تغير البكسلات. يحفظ بصمة APK وشهادته، وABI وإصدار النظام، ومزوّد OpenGL ES، وسجلات المحاكي والتطبيق والصور. خيار capture_video يضيف تسجيل قصير إن أتيح التشغيل اليدوي. GitHub قد لا يعرض workflow_dispatch لملف غير موجود على الفرع الافتراضي؛ لا تُضف Workflow للفرع الافتراضي فقط لحل ذلك. يمكن تفعيل الصورة والفيديو لفحص محلي أو ضبطه في الفرع المعزول.
- تسجيل إعلان Vulkan أو معلومات `cmd gpu vkjson` ليس تنفيذ Vulkan ولا إثبات توافق تعريف الهاتف. استخراج رقم ABI أو نجاح الإقلاع لا يعني أداءً مماثلاً لأي هاتف.
- لتشخيص إصدار RAFT أقدم **بلا بناء جديد**: بعد اختيار ناتج مسموح ومرجع SHA-256، افحص معرف الحزمة، ABI المكتبات داخل base/splits، بصمات شهادات جميع ملفات APK وتجانسها. على بيئة مصرح بها شغّل تثبيت base وكل splits المطلوبة معاً عبر `adb install-multiple` (أو `adb install` لملف APK واحد). لا تحوّل ملف XAPK كاملاً إلى مدخل adb. إذا توجد OBB أو بيانات إضافية فلا تعتبر نجاح التثبيت نجاح تشغيل، واتبع آلية مثبتة للإصدار. مع تطبيق يعمل، دوّن build/ABI/backend وحالة التثبيت، وحوّل سيناريو الاختبار إلى adb taps ولقطات وlogcat وفيديو عند الحاجة. لا ترفع APK/XAPK أو الأصول أو لقطات إصدار خاص في آثار هذا المستودع العام. لا تمرر مدخلات تنزيل أو تنفيذ غير موثوقة.
- سجلات GitHub Actions في [هذا الفرع](https://github.com/alwansan/raf/actions?query=branch%3Aqa%2Fandroid-emulator). [توثيق GitHub للـrunners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) و[توثيق Android للمحاكي وتسريعه](https://developer.android.com/studio/run/emulator-acceleration).
