# GT — Kernel 6 attribution to Dx11FFT

The three raw Unity log segments at [CL 3c26bb5](https://github.com/alwansan/CL/tree/3c26bb5d0f4de2cbffd42197dae9ae1372721659) contain 4,576 index-6 errors with zero registered kernels. Of these, 4,559 are followed immediately by the `Dx11FFT.ComputeFFT` frame, and 4,538 also have the following `WavesRendererFFT.RenderMaps` frame, with exact timestamp, UID, PID and TID equality for all matched lines. This supersedes the earlier lack of stack attribution for this session. The stack does not identify the failing Unity API or serialized asset GUID. [Aggregate evidence](../evidence/20261114_fft_kernel6_stack_and_source.json).

Mono.Cecil inspection of the original managed assembly whose SHA256 matches the ZIP2 manifest follows `Water.ShaderSet → ShaderSet.GetComputeShader → WavesRendererFFT → Dx11FFT`. Validation looks up the original compute by the object-name substring. The chooser checks the reference is non-null, hardware supports compute and resolution is at most 512, but does not check the registered kernel table. The constructor stores that reference and derives the numeric base index from the inherited log-size exponent and the two-channel bank flag. In `ComputeFFT`, six typed `SetTexture` and two typed `Dispatch` calls all use that receiver. Each pass binds three textures before dispatching. Pass 1 uses the temporary target as source and increments the index. Both dispatches use `(1, input.height, 1)`. The first original Unity compute call is `SetTexture`, so the stack alone cannot be taken as proof of an actual dispatch.

The named original ComputeShader was recovered from SHA-verified ZIP2. The original component MonoScript matches the managed ShaderSet, and its one-item serialized tail contains the original ComputeShader PPtr. UnityPy's fallback tree only exposed the built-in MonoBehaviour head, so the tail remains a byte-level correlation. The original source arithmetic for index 6 is exponent 8, single-channel bank and first pass. Source pair 6/7 is workgroup 512×1×1 with the same three authored resource names as the managed call sites. Twenty original programs were reconstructed and validated as translation candidates. All twenty serialized entries have one identical name and empty keyword bundles.

The next integration needs one ComputeShader identity, explicit candidate-to-entrypoint routing checked through Unity, and resource-name binding before comparing the two passes. Avoid inferring Unity runtime IDs directly from serialized positions. The original pixel FFT branch exists but needs its own authenticated shader restore and would not resolve the compute restoration. No XAPK started.
